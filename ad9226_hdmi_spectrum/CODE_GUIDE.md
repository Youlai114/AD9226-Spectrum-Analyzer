## 1. 一张图看懂全部数据流

```
27MHz 晶振 (引脚4)
  ├─ TMDS_rPLL → 371.25MHz ─ CLKDIV/5 → 74.25MHz ── 像素时钟 ──────────────┐
  └─ ad9226_pll → 54MHz ─── O_clk_adc(引脚76) ─→ AD9226                    │
                              └─ I_adc_d[11:0] 回来 ─→ 54MHz 采样/FFT 域   │
                                                                           │
[54MHz 域 —— 测量链]                                                      │
  ad9226_capture   抽取 ÷27/108/540/2700/1 → fs = 2M/500k/100k/20k/54M    │
       │ 输出 Q4 有符号样点 (±32768 = ±1V)                                 │
  fft4096          Hann/Rect/Black/Flat 加窗 → 4096点FFT → 开方 → 补偿      │
       │            → 16帧视频平均 → 1024 列 × 16bit 幅度 (65535=0dBFS)     │
       │            ↘ 基波列检测 + HD2~HD5 谐波窗口峰                      │
       ↓                                                                    │
  spec_data_if + spec_ram   乒乓双时钟缓存 (写54M/读74.25M, 防撕裂)         │
       ↓                                                                    │
[74.25MHz 域 —— 显示链] ←──────────────────────────────────────────────────┘
  spec_display     频谱页: 迹线/网格/瀑布背景/谐波标记/光标/读数/菜单
  wave_cap+wave_display  时域页: 边沿触发 1024 点, 前 256 点 4 倍内插
  video_top        模式选择 (频谱+瀑布 / 纯净频谱 / 时域) + 全部按键逻辑
  DVI_TX (高云IP)  RGB → TMDS → HDMI
```

**两个时钟域是理解本工程的第一道门**：所有测量在 54MHz 域算完，经乒乓 RAM 或
toggle 握手跨到 74.25MHz 像素域显示。凡是跨域的地方，代码里都有注释标明。

## 3. 关键数据格式（读代码前先背下来）

| 信号 | 格式 | 含义 | 出处 |
|---|---|---|---|
| ADC 原始 | 12bit 无符号 | 0..4095, 2048=0V | `ad9226_capture` |
| 样点 O_smp | **Q4** 16bit 有符号 | ±32768 = ±1V (×16) | `ad9226_capture` |
| 窗系数 | 12bit 无符号 | 0..4095 (=Q12) | `fft_tables.v` |
| 旋转因子 | **Q15** 16bit | cos/sin | `fft_tables.v` |
| 补偿系数 | **Q7** 11bit | 1024=1.000x | `magcomp_rom` |
| 幅度谱 | 16bit 线性 | **65535 = 0 dBFS** | `fft4096` 输出 |
| 光标频率 | 20bit 无符号 | Hz（宽频档为 kHz） | `spec_display` |
| dB 读数 | 12bit | \|dB\|×10（964=−96.4dB） | `spec_display` |

定点换算链（谁乘谁、为什么移位）在 `tools/model_fft.py` 头部注释里有完整推导，
RTL 与它**逐位一致**（cmp_fft 0 LSB）。

## 4. 每个文件一句话（存在理由）

| 文件 | 删掉它会怎样 |
|---|---|
| `ad9226_capture.v` | 没有样点（ADC 接口+抽取+去直流） |
| `fft4096.v` | 没有频谱（窗+FFT+开方+补偿+平均+基波/谐波检测） |
| `fft_tables.v` | 没有窗和旋转因子（脚本生成，勿手改） |
| `spec_data_if.v` | 换帧瞬间画面撕裂（乒乓 bank 切换+CDC） |
| `spec_ram.v` | 没有跨时钟缓存 |
| `spec_display.v` | 没有频谱页（迹线/瀑布/标记/光标/读数/菜单全在这） |
| `wave_cap.v` | 波形左右乱跑（边沿触发） |
| `wave_display.v` | 没有时域页 |
| `key_enc_ctrl.v` | 按键/编码器全失效 |
| `auto_span.v` | 没有 AUTO 一键定档 |
| `video_top.v` | 全部散件没有连线（例化+模式+CDC 枢纽） |
| `ui_font_rom.v` | 所有文字消失（5×7 字模） |
| `gw_stubs.v`(sim) | 顶层仿真无法运行（高云原语行为桩） |

## 6. 代码里标了 ★ 的地方 = 踩过坑的教训，改前必读

全工程共 9 处 `★` 注释，每处都是真实调试过的结论，例如：
- `wave_display.v`：拼接 `{bit,reg}` 无符号陷阱（过零瞬变）
- `fft4096.v`：乘积必须先落宽 wire 再移位（13bit 回绕）
- `spec_display.v`：双 dabble 步数与字段宽度必须一致
- `build.tcl`：gw_sh 必须用 open_project，否则 SDC 静默失效

搜索 `★` 即可定位全部。

## 7. 已知边界与潜在 BUG 清单（维护者必读）

### 7.1 仍存在的设计边界（已知、可解释、未修）
| 现象 | 原因与量级 | 规避 |
|---|---|---|
| 换档/换窗后 1~2 帧过渡 | 谱线为旧参数；标记/H表/F0 已跨度门控隐藏，文字立即切换 | 等待即恢复 |
| 瀑布历史跨档混合 | 换档后最长 128 帧含旧档频率（Span10k 约 27s） | 等历史滚出 |
| H5 窗口边界 | 基波在两 bin 正中时 5 次谐波列误差 ±2.5 列 > ±2 搜索窗，H5 可能读低 | H2~H4 不受影响；微调频率 |
| Δ 参考快照 | 跳峰后 17ms 内进增量，参考取旧列值并冻结 | 等一帧再进 / 重进 |
| 光标读数滞后 1 帧 | 抓幅机制固有 | — |
| Flat Top 微饱和 | +0.08dB | 校准用 <0dBFS 信号 |
| 宽频档镜像 | 27~54MHz 折叠（无模拟抗混叠） | 信号源干净 |
| 平均响应 τ=16 帧 | Span1M ~0.1s、慢档 4 帧 ~0.8s | 测瞬变时注意 |

### 7.2 上板才能确认的硬件风险
| 风险 | 现象 | 调整点 |
|---|---|---|
| AD9226 直流偏置 | 0Hz 异常大峰 | `ad9226_capture.v` 的 `13'sd2048` |
| 编码器抖动 | 偶发方向反转 | `key_enc_ctrl.v` 的 `ENC_STEP` 4→2 |
| HDMI 兼容 | 个别显示器黑屏 | 换线/换口 |
| 杜邦线接触 | 数据跳变/花屏 | 压紧，CLK 最短 |

### 7.3 TB 已知怪癖
tb_fft 的 `+FRAMES` 多帧驱动节奏不稳（单帧 0 LSB 可靠）；多帧验证一律用 tb_top。
PPM 落盘 1 刺采样偏移已在 TB 补偿；initial 里直发 req 脉冲会与 ST_MAG 竞态。

### 7.4 历史已修的坑（改动前搜 ★）
拼接无符号 / 乘积宽度回绕 / dabble 步数 / twiddle 半表刻度 / BSRAM X 污染 /
put 参数转置 / 前缀拼接移位 / FSM else 误删 / 多驱动 / SDC 静默失效 / license U+202A——共 10+ 处 ★ 注释。

## 8. 硬件提醒（读代码时容易忘记的物理事实）

- 板载晶振是 **27MHz**（不是 50），一切 PLL 参数由此而来
- AD9226 模块 5V 供电、输入内部偏置 2V、满量程约 2Vpp
- 引脚 54/55/56 是高云 SSPI 专用脚，永远不能占用
- 全部按键/编码器低有效（内部上拉），S2(88) 是唯一硬件复位
